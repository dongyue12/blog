## tmux 是什么

日常用终端最常见的两个麻烦：一是 SSH 一断，正在跑的命令就跟着死了；二是一个终端窗口里只能干一件事，看日志的时候就没法敲命令。

tmux 同时解决这两件事。它把自己放在终端和程序之间：程序跑在 tmux 里，终端只是 tmux 的一个"窗户"。窗户关掉，程序还在；下次打开窗户，接回去就是原样。至于一个窗口里切成好几块同时干几件事，是它的附带能力。

## 三层结构

tmux 用三层来组织东西，理解这三个词，剩下的都是查表。

| 层级 | 说明 |
| --- | --- |
| 会话 | 最外层，一个项目一个会话。可以分离（扔到后台）和重连（接回来） |
| 窗口 | 会话里的标签页，一个任务一个窗口 |
| 面板 | 窗口里的分屏，可以左右或上下切 |

所以日常习惯是：**一个项目开一个会话，会话里按任务分窗口，需要对照时再分面板**。不要在同一个窗口里开十个面板，那是另一种混乱。

所有快捷键都要先按**前缀键**（默认 Ctrl+b），松开后再按命令键。这个设计是为了避免和普通程序抢按键。

## 安装tmux

```bash
# fedora
sudo dnf install tmux

# Ubuntu/Debian
sudo apt-get install tmux

# CentOS/RHEL
sudo yum install tmux

# macOS (使用 Homebrew)
brew install tmux
```

装完直接敲 tmux 就进去了。第一次进去会看到底部多一条状态栏，那就是 tmux 在工作。

## 配置tmux

> 配置文件位于 ~/.config/tmux/tmux.conf，老版本也会读 ~/.tmux.conf。

配置的原则是**只留真正影响使用的项**，配色之类的可以以后再折腾。

```bash
$ cat ~/.config/tmux/tmux.conf
# 鼠标选中、切面板、拖边框
set -g mouse on

# 窗口和面板编号从 1 开始（默认从 0，按起来别扭）
set -g base-index 1
setw -g pane-base-index 1

# 关掉窗口后编号自动补位，不留空号
set -g renumber-windows on

# 真彩色。用 screen-256color 会让 nvim 主题发灰
set -g default-terminal "tmux-256color"
set -ga terminal-features ",foot*:RGB"

# ESC 不再等 10ms，vim/nvim 里手感明显变快
set -sg escape-time 0

# 滚动缓冲，默认只有 2000 行，看日志不够
set -g history-limit 50000

# 允许程序通过 OSC52 写系统剪贴板
set -g set-clipboard on

# 切回终端时通知应用（配合 nvim 自动重载文件）
set -g focus-events on
```

改完让配置生效：

```bash
$ tmux source-file ~/.config/tmux/tmux.conf
```

有个细节要注意：source-file 只是"再执行一遍配置"，**删掉的项不会自动失效**。真要彻底干净，得重启服务（会话会全部丢失）。

### 命令管理

常用命令与快捷键

tmux 的所有操作都需要先按下前缀键（默认是 Ctrl+b），然后输入命令键。

#### 会话管理

会话是你和 tmux 之间最长久的连接。养成"先开会话再干活"的习惯，断线就不会丢东西。

| 命令/快捷键 | 说明 |
| --- | --- |
| tmux new -s <name> | 创建名为 name 的新会话 |
| tmux ls | 列出所有会话 |
| tmux a/attach -t <name> | 重新连接到指定会话 |
| Ctrl+b d | 分离当前会话（会话继续后台运行） |
| Ctrl+b $ | 重命名当前会话 |
| Ctrl+b s | 切换会话 |
| tmux kill-session -t <name> | 杀死指定会话 |

#### 窗口管理

一个窗口就是一个全屏界面。任务之间切来切去，比在同一个面板里反复 Ctrl+C 干净得多。

| 命令/快捷键 | 说明 |
| --- | --- |
| Ctrl+b c | 创建新窗口 |
| Ctrl+b n | 切换到下一个窗口 |
| Ctrl+b p | 切换到上一个窗口 |
| Ctrl+b <number> | 切换到指定编号的窗口 |
| Ctrl+b , | 重命名当前窗口 |
| Ctrl+b & | 关闭当前窗口 |

#### 面板管理

面板用来"同时看两件事"：左边改代码，右边跑命令；或者上面敲命令，下面盯日志。

| 命令/快捷键 | 说明 |
| --- | --- |
| Ctrl+b % | 垂直分割当前面板（左右并排） |
| Ctrl+b " | 水平分割当前面板（上下堆叠） |
| Ctrl+b <arrow> | 在面板间移动焦点 |
| Ctrl+b o | 按顺序切到下一个面板 |
| Ctrl+b q | 显示面板编号，按数字跳过去 |
| Ctrl+b z | 最大化/恢复当前面板 |
| Ctrl+b Space | 切换面板布局 |
| Ctrl+b { 或 } | 把当前面板向前/向后移动位置 |
| Ctrl+b x | 关闭当前面板 |

## 复制与粘贴

> tmux 会接手鼠标选中和滚轮，所以要单独记这一套机制。

进入复制模式后可以做三件事：翻历史、搜索、选中复制。

| 命令/快捷键 | 说明 |
| --- | --- |
| Ctrl+b [ | 进入复制模式 |
| Ctrl+b ] | 从 tmux 缓冲区粘贴 |
| q | 退出复制模式（按键没反应时先试这个） |
| 按住 Shift 拖选 | 绕过 tmux，直接用终端自己的选择复制到系统剪贴板 |

让 tmux 的复制写进系统剪贴板（foot、kitty、wezterm、iTerm2 都支持 OSC52）：

```bash
$ cat ~/.config/tmux/tmux.conf
set -g set-clipboard on
```

## vi 键位

复制模式有两套键表，由 mode-keys 决定：emacs（默认）和 vi。喜欢 vim 的人切过去会顺手很多。

### 为什么按空格会跳到底部

这是最常见的困惑。同一个键在两套键表里含义完全不同：

| 按键 | emacs 键表（默认） | vi 键表 |
| --- | --- | --- |
| 空格 | 向下翻一页 | 标记选中起点 |
| 回车 | 复制并退出 | 复制并退出 |
| v | 没有绑定 | 标记选中起点 |

所以按空格"跳到底部"不是配置坏了，是空格在 emacs 键表里就是 page-down，连按几下自然到底。

### 配置

```bash
$ cat ~/.config/tmux/tmux.conf
# emacs 键表里空格是翻页，vi 键表里空格才是"开始选择"
setw -g mode-keys vi

# 这两个键 vi 键表里默认没有绑定，需要自己加
bind -T copy-mode-vi v send -X begin-selection
bind -T copy-mode-vi y send -X copy-pipe-and-cancel
```

### vi 键位下的完整操作

| 命令/快捷键 | 说明 |
| --- | --- |
| Ctrl+b [ | 进入复制模式 |
| h j k l 或方向键 | 移动光标 |
| Ctrl+u / Ctrl+d | 向上/向下半屏 |
| Ctrl+b / Ctrl+f | 向上/向下整屏 |
| g / G | 跳到最顶部/最底部 |
| / 或 ? | 向下/向上搜索 |
| 空格 或 v | 标记选中起点 |
| y 或 回车 | 复制并退出 |
| q | 不复制，直接退出 |

完整流程是这样的：

```
Ctrl+b [       进入复制模式
/error         搜索
空格           开始选
移动光标       拉选范围
y              复制并退出
Ctrl+b ]       粘贴
```

> mode-keys 改的只是按键绑定，翻页、搜索这些底层动作是一样的。

## 同步输入

> 一个窗口里的多个面板同时执行相同命令，批量操作时用。

```
Ctrl+b 然后输入 :setw synchronize-panes on
```

关掉：

```
:setw synchronize-panes off
```

多台机器一起改配置、一起重启服务时，比开一堆 SSH 窗口快得多。用完记得关，否则你以为在敲一台机器，其实敲了三台。

## 会话持久化

> tmux 只能保证进程不退出，机器重启就全没了。要断电也能恢复，必须上插件。

| 插件 | 说明 |
| --- | --- |
| TPM | tmux 的插件管理器，装插件的前提 |
| tmux-resurrect | 手动保存/恢复会话布局和正在跑的程序 |
| tmux-continuum | 在 resurrect 之上自动定时保存、开机自动恢复 |

```bash
$ git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm
```

```bash
$ cat ~/.config/tmux/tmux.conf
set -g @plugin 'tmux-plugins/tpm'
set -g @plugin 'tmux-plugins/tmux-resurrect'
set -g @plugin 'tmux-plugins/tmux-continuum'

run '~/.tmux/plugins/tpm/tpm'
```

装完按 Ctrl+b I 安装插件。

不装插件也可以手动记下当前布局，换机器后用 select-layout 还原：

```bash
$ tmux list-windows -F '#{window_name}: #{window_layout}'
```

## 常见问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 关掉终端后程序被杀了 | 没在 tmux 里跑 | 先 tmux new -s work 再启动 |
| Ctrl+b 没反应 | 嵌套 tmux，前缀键被外层吃掉 | 连按两次 Ctrl+b |
| 按键全都没反应 | 误入了复制模式 | 按 q 退出 |
| 鼠标选中复制不到剪贴板 | tmux 接手了选择 | 按住 Shift 拖选，或开 set-clipboard |
| 看不到历史输出 | 已经滚到缓冲上限 | 调大 history-limit |
| 配置改了没生效 | 没重载 | tmux source-file 配置文件路径 |
| 改了配置删掉的项还在 | source-file 只叠加不撤销 | 重启 tmux 服务，或手动 set 回默认值 |

## 一句话原则

终端里跑的长任务一律放进 tmux。编译、下载、SSH、看日志——断网、关笔记本、SSH 掉线，回来 tmux attach 一切都还在。
