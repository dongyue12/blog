当你同时维护多个远程仓库时（比如 GitHub 和自建 Git 服务器），每次都分别推送会很麻烦。Git 远程组可以让你一条命令推送到所有远程。

## 添加远程

先添加好你的远程仓库：

```
git remote add origin xxx
git remote add gitea xxx
```

查看确认：

```
git remote -v
```


## 配置远程组

用 `git config` 定义一个组，把多个远程名字写在一起：

```
git config remotes.all "origin gitea"
```

这会生成以下配置：

```
[remotes "all"]
    all = origin gitea
```

然后一条命令同时推送到所有远程：

```
git push all
```

`git fetch all` 也同样支持，会从所有远程拉取：

```
git fetch all
```

## 查看配置

```
git config --local --list | findstr remotes
```

也可以直接用编辑器打开配置文件：

```
git config -e
```

这会用默认编辑器打开 `.git/config`，可以直接修改。

## 删除远程组

```
git config --unset remotes.all
```

## Git 核心配置说明

`git config -e` 打开的 `.git/config` 中，`[core]` 部分包含以下默认配置：

| 配置 | 含义 |
|---|---|
| `repositoryformatversion = 0` | Git 仓库格式版本。0 是当前标准版本，兼容所有现代 Git |
| `filemode = false` | 不跟踪文件权限变化。Windows 上默认为 false，因为 NTFS 没有 POSIX 权限 |
| `bare = false` | 非裸仓库。false 表示有工作目录（可以正常开发），true 表示纯远程仓库 |
| `logallrefupdates = true` | 记录所有引用的更新日志（reflog）。让你能用 `git reflog` 找回误删的提交 |
| `symlinks = false` | 不支持符号链接。Windows 上默认关闭 |
| `ignorecase = true` | 文件名大小写不敏感。`README.md` 和 `readme.md` 视为同一个文件，Windows/macOS 默认开启 |

这些基本都是 Windows 上的 Git 自动设置的默认值，一般不需要改动。

## 与其他方式的对比

还有一种方式是用 `git remote set-url --add --push`，它修改的是单个 remote 的 pushurl，让 `git push origin` 同时推送到多个地址：

```
git remote set-url --add --push origin xxx
git remote set-url --add --push origin xxx
```

两种方式各有适用场景：

| 方式 | 命令 | 适用场景 |
| --- | --- | --- |
| 远程组 | `git config remotes.all "origin gitea"` | 需要区分 fetch 和 push 目标，灵活组合 |
| pushurl | `git remote set-url --add --push origin <url>` | 只想让默认 push 同时发往多个地址 |

远程组的优势在于可以自由组合任意远程，而 pushurl 方式只对单一 remote 有效。
